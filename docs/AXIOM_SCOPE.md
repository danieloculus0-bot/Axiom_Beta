# Axiom product boundary

Axiom is the local-first **manufacturing and business operations/ERP** product. The fact that a repository belongs to the same GitHub account does **not** make it an Axiom module, runtime dependency, bundled application, or planned merger.

## Axiom scope
Manufacturing operations, approved quality and production records, estimating/quoting, purchasing, maintenance, controlled document handoffs, and the related interfaces that are explicitly implemented and tested.

## Independent products
- **BEAN Core:** independent reasoning, evidence and learning system; optional adapters may assist Axiom without absorbing Core.
- **AIscend:** independent financial trading and research system. Not an Axiom application.
- **FUN and other games:** standalone entertainment projects. No game launcher, assets, controls or gameplay in Axiom.
- **BEAN-Rider:** independent vehicle/OBD research, not an ERP module.
- **venvWin:** independent OS/compatibility work, not an ERP module.
- **EZ-FEA:** independent engineering solver, which may exchange reviewed engineering evidence through a versioned interface but remains its own product.
- **JET-ERP:** separate architecture/research project; no automatic code/data migration into Axiom.
- **Other portfolio repositories:** independent by default until the actual business use case and integration contract are approved.

## Integration rule
Cross-product cooperation must be explicit and narrow: versioned APIs, controlled file transfers or approved data contracts. Shared branding, a portfolio landing page, README links, and common CI evidence do **not** establish ownership, product inclusion, live synchronization or permission to bundle.
